## 三条不重叠的"只有 X 能定位 Y"（与 v2 一致，本树复现）

1. **结构化故障（wrong_item_pick / format_violation）**：确定性内容信号可定位（Tier-A 契约 oracle 1.000），
   但须对照常量基线 0.375/该族先验 1.000 —— Who&When 的 0.833/0.417 是**低于先验**的，说明该族靠先验就送分，
   判官的"定位"反而不及无脑答 Synthesizer。
2. **hallucinate**：内容感知判官能定位（all_at_once 0.528，先验 0.000 ⇒ 真定位），但方法间差异极大
   （all_at_once 0.528 vs binary_search 0.083）。
3. **context_drift**：对所有输出阅读型方法全盲（四方法 0.083–0.389，含本表的 LLM 判官；Tier-A 的
   span/内容轨同样近随机 0.028），**只有轨迹结构信号能定位**（`agentfault.resolved_input` 观察型检测器 36/36 = 1.000，
   见 `RESULTS_CONTENT_CTXDRIFT.md`）。

## 必读局限（诚实条款）

- **GLM-5.2 跨族复核已跑完**（`whowhen_results_glm52.json`）。本树 DeepSeek + GLM 双 judge:
  DeepSeek = 幻觉注入副 LLM 的同族(SPEC §2 同族偏差风险),GLM-5.2 是跨族外检。
  **跨族复核结论**:GLM all_at_once **0.240**(hallucinate **0.361** / wrong_item_pick 0.500 / format_violation 0.333 / context_drift **0.000**)
  —— (1) hallucinate 跨族仍 >0 先验(GLM 0.361 vs DeepSeek 0.528)⇒ "内容感知判官能定位 hallucinate" 跨族成立;
  (2) context_drift 跨族仍 0.000(DeepSeek 0.194)⇒ "输出阅读型方法对静默上下文故障全盲" 跨族成立;
  (3) GLM 分低于 DeepSeek ⇒ **同族膨胀未见**(若有同族虚高,跨族应降;实际两端都 >0 先验,定位结论稳)。
  v2 GLM all_at_once 0.292(hallu 0.472)互为对照。
- **解析率 94–96/96**：`step_by_step` 2 条、`a2p` 1 条判官输出未能解析（计为漏预测，分母仍 96）。
  这是 LLM 判官的常态，不修补；逐方法解析率见上表"解析率"列与 `whowhen_results.json` 的 `parsed_predictions`。
- **w/o ground-truth-answer 设定**：`ground_truth = "N/A"`（开放式推荐任务无唯一答案），比 Who&When 默认
  把真答案贴进 prompt 更难；对齐他们的 w/o-GT-answer 设置。
- **单预测方法**：对 MRCBench，排名表 = [预测] + 其余 canonical 名补齐，故 @3/@5/@R、mrr、ndcg@K 全是
  canonical-padding 产物（1 个预测、4 个候选），**只有 Hit@1 有判别力**，且应与 native agent accuracy 一致（双协议互校）。
- **`binary_search` 的歧义答案 tie-break 是 `random.randint`**；harness 在每次 run 前固定 `random.seed(0)`（vendored 代码未改）。
- **context_drift (n=36) 对本表所有方法按设计全盲**：注入删的是下游 agent **输入**里的上游消息，四个 agent 的
  **输出**都还在、形态正常 ⇒ 输出阅读型判官看到的 transcript 没有可见症状，**低分是预期、预期结果**，
  是"输出阅读型归因看不见静默上下文故障"的证据，不是 harness/方法的缺陷。case JSON 不漏任何删除线索
  （adapter 检查 8a–8c：无元数据字段、无泄漏词、跨族结构同形）。
